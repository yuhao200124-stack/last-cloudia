# 基础属性分类与计算接入

沿用现有网站、技能 ID、配装方案、角色来源绑定与删除决定。没有重新建站。

## 核算口径

现有 20 张旧分类表合并，按来源 URL（无 URL 时按原 ID）去重：935 个。
全部技能主表：933 个。旧分类页另有格雷拉特家的血统、龙族斩灭者两个来源，均不属于本轮基础属性。保留原位置，不改主表内容。

基础属性：181 个不同技能，263 次分类展示：HP 25、MP 8、攻击力 78、法强 43、防御力 64、魔抗 45。一个技能可以同时在多个项目出现。总数不是六列相加，而是按来源去重。

基础属性完整接入 134 个，部分接入 2 个，45 个已记录属性目标与已知数值，但触发状态、动态值、层级或状态覆盖关系仍待对应类型确认。这里的“完整”仅针对该技能的六维属性分量，不声称技能其它效果全部接入。

不把 HP/MP 回复、消耗、回复上限、吸血、伤害随属性变化、敌方防御参照或属性下降免疫当作自身基础属性提升。开场转换只归入接受加成的属性，原属性不因此减少。实际有减益的技能保留负号。

## 数据维护

- `docs/basic-stat-registry.json` 是可复核规则原稿：原技能 ID、完整原文、来源、属性项目、分段效果、条件、确认状态。
- `scripts/build-basic-stats.mjs` 校验 ID/完整原文，生成计算器规则目录、表格标记及去重计数。原文变更时停止生成，避免沿用旧规则。
- 新“基础属性”分类引用主表已有 ID，不制造六份可选技能。
- 来源为已完成的技能文本校对及 `docs/skill-audit-2026-09-24.json`，不是新一轮游戏版本检验。

## 计算边界

已接入：直接百分比、固定基础属性、已知装备条件、满血/濒死持续条件、装备自身强化与开场属性转换。按现有面板公式处理，不把属性提升再当一次伤害增幅。

固定属性使用常驻层 add，即 `(基础 + 装备 + 固定加成) × (1 + 常驻百分比)`；依据见已有 `docs/panel-calculation.md` 的 `BuffAddMul.Calc` 原生字段顺序。校对缓存 Goldmine 的 HP Plus（130000026090）明确为 Update Base HP，flat=500、isBase=true；Magic Up 明确为 Update Base INT。神圣光环（130000011800）的装备范围为八种武器，STR/INT 各 25%，不是角色最终面板乘 1.25。

满血/濒死放在现有实时属性层；属性转换沿用开场快照；装备自身提升先作用于每件具体装备。任意防具条件由长袍、衣服、铠甲状态推导，双武器时无防具。

开场40秒、永久状态与觉醒类已按用户确认接入当前状态开关，参见 `buff-conditions-2026-09-24.md`。随机触发、当前叠层、当前HP/MP曲线、特定队友、Boss Wave、未知状态分组、该次伤害专用属性修正等仍不猜测状态或套最大值，继续标为待确认。

多属性重复展示不产生重复计入。角色原有已拆分规则、确认数据与删除/停用状态保留原来源 ID。用户改名可保留规则；改效果文本时失效并回到原有确认/识别流程。已保存的手动规则继续优先。

复合技能的未接入部分保持独立待确认项，不因一部分属性已识别就把整个技能标为已完成。

## 验证

新增检查覆盖：去重计数、六项目归类、三属性重复展示但一次选装、正负与固定属性计算、HP 条件开关、装备条件、武器自身强化、属性传到伤害、原角色来源去重及删除/停用保留、编辑原文失效、未确认效果不计入。

页面使用原应用的 DOM 模拟运行检查，核对分类切换、搜索和快照传输；当前没有可用的浏览器预览，未将这些检查描述为真实浏览器测试。
