# 配装工作区：技能表选技能，计算器算加成（2026-09-29）

## 用户要求
（2026-09-29 后来：用户试过把配装改到技能分类页，又决定恢复这里的做法——配装从角色页进来，先确认角色，再配装。之后又决定：点“配装”不留在计算器里，**整个窗口回到首页**，还是左表右结果。）
把配装和计算器连起来：
- 配装之前先把计算器现在显示的内容算好。
- 在技能表里点“+”选一个技能，计算器自动算出这个技能带来多少加成。
- 和旧配装器一样，到主页面的技能表里去选。

用户确认的做法：
- 从游戏数据技能表选；并排显示，像旧配装工作区，手机上上下切换。
- 只在点“+”时计算，不要“试算”。
- 显示伤害提升百分比和具体变化。
- 角色自带、但技能表里没有的 SC 技能：“直接显示已经添加了，但是费用要改成0排列在最下面”。
- SC 合计和能力盘突破（7／12／20）都要。
- 原来的配装面板并进工作区，去掉搜索添加。
- 首页（单独打开的技能表）只供查看，没有“+”。

## 怎么用
1. 角色页 → 计算器 → 点“配装”（结果卡下面）：整个窗口换到首页 `index.html?character=角色编号`。
   - 左边是首页的游戏数据技能表（原来的样子），每行最右边有“+”。
   - 右边是计算器（`damage-calculator.html?character=…&embedded=build`，放在页面里的小框），显示结果和配装面板。
   - 单独打开首页（没有 `?character=`）时只供查看，没有工具栏也没有“+”。
2. **工具栏**（技能表上面）：
   - “技能表／战斗设置”切换左边显示技能表，还是计算器的招式、开关、目标（这时计算器占满整行）；
   - “收起结果”：把右边收起，技能表占满整行；
   - “退出配装”：回到这个角色的角色页。
   - 工具栏上显示角色名、已选数、SC 合计、当前配装每次伤害，和刚加入的技能的收益。
3. **加技能**：点“+”加入，按钮变成“✓”，下面显示收益；再点一次取消。每次加减都会重新计算。计算器还没准备好时“+”是灰的。
4. **手机**（窄于 900px）：工具栏是“技能表／战斗设置／结果与配装”三选一。技能表的“+”这一列固定在右边，左右滑动表格时也看得到。
5. **页面之间的消息**：计算器 → 首页 `lc-damage-ready`、`lc-build-state`；首页 → 计算器 `lc-build-toggle`（加／取消）、`lc-build-view`（显示结果还是战斗设置）、`lc-build-hello`。配装只在这个小框里算（`build.on` 只有在 `embedded=build` 时才打开），单独打开计算器时主结果不变。

## 隐藏用不到的技能（全输出／半肉／全肉／不隐藏）
2026-09-29 用户：“我配装的时候把那些我用不到的加成都隐藏起来……弄成4个选择……可以在搜索框后面弄一个”。
- 首页技能表搜索框后面四个按钮，只在配装时出现，选哪个记在浏览器里，默认“不隐藏”。
- 分组（用户确认）：
  - 输出：造成伤害、伤害上限、特攻、暴击、Break值、反击、攻击力／法强、特技充能·必杀、魔法·咏唱。
  - 防御：受到伤害、HP／防御力／魔抗（和属性耐性）、回复。
  - 其他（永远不隐藏）：异常（耐性和赋予都算；用户：全输出也要异常耐性）、MP、移动与行动、装备·种族、信仰、金钱·经验、待确认。
- 全输出：隐藏防御和“对当前招式没用的输出”，其他留着；半肉：只隐藏对当前招式没用的输出；全肉：隐藏全部输出；不隐藏。
- 对当前招式有没有用，按每条效果的属性和攻击类型（技能分类数据）对当前招式：
  - 属性要对上（冰招式隐藏火、雷……的加成）；攻击力／法强只留招式用的那个（按计算器第 1 击用的属性）。
  - 攻击类型：招式的 SKILL_TYPE（普攻 9、特技 1、魔法 2、超必杀 5），用法强打的再加上魔法。实测（游戏脚本）：洛琪希的水弹是特技，吃“物理攻击”（勇者 +20%）也吃“冰魔法”加成（冰魔法超阶增幅 +30%），所以水弹不隐藏物理／特技的加成；冰霜新星（魔法）才隐藏。
  - 特攻不按种族、也不按攻击类型隐藏（用户：全都留下），只在全肉时隐藏。
  - 一条效果是副作用（例如勇者的“受到伤害 +10%”）时不算防御。一个技能只要有一条效果该留就留。
- 数据：game-skill-data.js 每个技能的 cls.e = [大类, 基础属性项, 属性, 攻击类型, 是否副作用]（scripts/build-game-skill-table.mjs 从 docs/skill-classes-draft.json 取），页面不显示。计算器把招式的属性、SKILL_TYPE、是否用法强（lc-build-state 的 move）发给首页。

## 配装面板
- **启用**：在首页配装时，主结果按配装计算。
- **自带被动**（2026-09-29 用户：“直接把这里头的内容都删掉，除那个专武都默认开启，专武由伤害计算器那个页面决定”）：
  - 配装面板里不再有说明文字和开关；个性、固有免费被动（能力盘上 SC 99 的）、超越、加护永远都算。
  - 专武按计算器自己的“专武”选项（未装备／某一件／全部／其他），和角色页里的计算器是同一个设置（按角色存在浏览器里），在首页配装时可以在“战斗设置”里改。配装面板的说明行写出当前的专武。
  - 保存的配装不再记专武和自带开关；以前存的这两项不再使用。
- **SC 合计与能力盘突破**：
  - 一破／二破／三破可以分别开关，默认全开。
  - 规则与旧技能表完全相同（`dist/build-sc.mjs`）：按 7、12、20 的顺序，每个打开的突破让 SC 不超过它的已选技能里、SC 最高的一个免费。
  - 免费的技能显示“0　一破（原 7）”这样。
- **每个技能的收益**：
  - 算法：去掉这个技能后，伤害会少多少（当前配装每次伤害 ÷ 去掉它后的每次伤害 − 1）。
  - **具体变化**：比较有它和没有它时本招式第 1 击实际吃到的数值，只列出变了的项：
    - 法强／攻击力、暴击率、伤害上限；
    - 特攻倍率、核心前倍率（攻／受／减伤）、属性抗性；
    - 核心后修正、暴击伤害倍率。
  - 没有任何变化时写“本招式没有变化”。
  - 计算顺序：先算刚加入的技能，然后是其他已选技能，最后是能力盘自带技能。
  - 都按随机 0.95、第一条伤害弹道比较，和结果卡的“每次期望”一致。
- **能力盘自带（0 SC，固定在最下面）**（2026-09-29 用户改：“这些你先去搞清楚技能来源然后再说他是多少SC” → 选了“算 0 SC（和原来技能表一样）”）：
  - 什么技能算：角色自己能力盘上所有要花 SC 的技能（游戏数据 SC 1～98），不管技能表里有没有、圣物能不能学。
    - 例：洛琪希 19 个——专属的月光II、贯导、杖神阶增幅……，和通用的冰攻击提升III（13）、冰暴击提升（12）、巨型护盾II（14）等。
    - 查证：洛琪希推荐配装的 12 个技能全是她能力盘上的（限界突破 2～4 阶段的区域），游戏里的 SC 合计 97。
    - 用户账号里的洛琪希把能力盘上 30 个技能全装着（读取器报告），不算 SC 99 的合计 146。
  - 所选技能和它们之间有一条“能力盘自带 N 个 · 0 SC”的横条，点一下收起／展开这些行（2026-09-29 用户要求；记在浏览器里）。
  - 永远算在配装里，不能移除，按原 SC 从大到小排在最下面，标“能力盘自带”（鼠标停在标签上显示是限界突破第几阶段的区域、圣物能不能学），也有自己的收益行。
  - 首页技能表里这些技能不显示“+”，显示“自带”和收益。
  - 只有另外从圣物学的技能用“+”选、花 SC，一破／二破／三破也只用在这些上。
  - 以前保存的配装里选过的能力盘技能，载入时自动去掉（它们本来就在）。“恢复角色推荐配装”会说明其中几个是能力盘自带。
  - 判断依据：game-data/c/<dress>.json 的 ownPassives（来自 UnitDressAbilityPieceMst 的技能格，limitBreak 是那个区域的限界突破阶段，common 表示圣物也能学）。
- **说明段落已删**（2026-09-29 用户：“把这段都删掉”）：SC 合计下面原来那段“当前配装每次…配装前…已选…能力盘自带…专武…收益＝…”不再显示；那一行只在出错时显示提示（例如“配装报告里没有这个角色”）。每次伤害看首页工具栏。
- **配装前（只有自带）**：没有选任何技能时的每次伤害，以及当前配装比它高多少。
- **保存与选择**（2026-09-29 用户：“改简单点就留保存配装还有另存为新配装，还有清空所选，还有配装选择…保存配装的时候出一个小窗口…给我输出名字”）：
  - “配装”下拉框：这个角色保存过的配装（最新的在前），选哪个就载入哪个；旁边“删除”删当前这套，先在小窗口里问一句。
  - 按钮只留“保存配装”“另存为新配装”“清空所选”。
  - 点保存会在按钮下面弹出一个小窗口填名字（回车保存、Esc 或点别处取消）：保存配装＝覆盖当前这套（名字默认是它原来的名字，可以顺便改名）；另存为新配装＝新建一套（默认“配装方案 N”）。
  - 去掉了：配装名称输入框、恢复角色推荐配装、从配装报告载入已装被动、重算全部收益、已保存配装列表（载入／改名／删除）。
  - 按每 SC 收益推荐：暂时留着，用户说以后要改，等用户说怎么改。
  - 保存的配装多了突破设置；以前存的没有这一项，按三个都开。
- **去掉的功能**：搜索添加、候选按钮上的“试算”、推荐里“只算搜索到的被动”（依赖搜索框）。
