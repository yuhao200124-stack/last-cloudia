# 计算器长期规则

## 2026-09-24 用户确认：同类型 Buff 只保留一份

魔术指导的法强 +65% 会替换同组原有的法强 +50%（EX 灵气），不能得到 +115%。
这是用户明确确认的机制，不再保留“指导与 EX 相加”的试算分支。

- 替换按效果所属 Buff 组判断，不按“都增加法强”判断。
- 月光II的满血条件属性是独立被动，仍按满血条件判断；它不会随 EX 被替换。
- 技能内攻击修正是技能参数，不属于这个 Buff 互斥组。
- 魔法上限是单独效果，按来源防止重复计入。
- 不推广为“所有 Buff 永远取最大值”；当前明确启用的同组 Buff 替换原组，其他胜出规则需各自依据。
- 观察面板已包含所选 Buff 时，复用其状态，不再次乘算或叠加。

## 通用引擎与专属资料分开

通用层负责面板与装备计算、Buff 分组替换、属性层、技能参数、攻防与抗性、伤害加成、上限、暴击以及按数据指定的命中修正。不能在此层写角色名、角色基础数值、特定技能的固定倍率。

`runtime-buff-engine.mjs` 只消费已确认的属性、数值、层级、分组与互斥策略；`runtime-buff-definitions.mjs` 保存已核实的共享状态定义和法术数据。列入定义不代表每个角色都拥有该法术；可用项由当前角色资料决定。未知分组不可冒用已有组。

`character-combat-rules.mjs` 与现有角色资料保存专属规则。洛琪希的冰魔法命中×2、单段×0.6、限定特殊魔法类型等必须绑定角色与来源，不是所有角色或所有双刀的默认值。其个性中的 Boss 特攻也不能自动赋予其他角色。

读取器记录客观观察；网页计算与预测不得回写成读取器实测。


## 2026-09-24 用户确认：战斗选项与核对草稿

- 战斗选项用「双刀」「特攻」「break」「满血」。取消魔法暴击资格勾选框；结果始终显示普通和暴击每段伤害。暴击对照值不等于赋予魔法暴击资格，也不把零暴击率的整次期望改成会暴击。
- 满血控制已经确认的满血条件规则；不满血不等于濒死。连续 HP 属性机制仍在每 Wave 开始和 HP 变化时判断。
- 读取器观察值保持原样。通用属性层先用未删除、条件合格的候选解释观察状态，再应用本次满血条件，最后处理同组 Buff 替换。所有属性和来源按数据识别，不写入角色基础数值。
- 多效果规则在删除或排除一项后，剩余项保留原效果索引，避免来源重复计入；删除项不会因条件切换恢复。
- 「保存并返回」保存未完成草稿也能返回；计算资格另行验证。未完成资料在计算区说明，不使用旧结果或自动确认未知加成。
- 核对草稿以报告内容 SHA256 和角色 Unit ID 隔离，保留最近四份；包括采用决定、面板时刻、手填面板、读取对应、补充加成和攻击时观察。刷新后重新导入同一份报告恢复，原始大报告不存浏览器。
- 本地保存失败明确提示并留在核对页，不能报告保存成功。


## 2026-09-24 后续修正：恢复暴击选项并联动核对

本节覆盖上节“取消魔法暴击资格勾选框”的界面决定。用户要求保留「暴击」，控制暴击相关技能、暴伤及附带加成是否参加本次计算，而不仅改变最终暴击率。

- 暴击开关由统一选择状态驱动网站候选、读取器候选、补充项和最终伤害。关闭时排除暴击率、暴伤、明确的暴击触发规则，以及同一规则内暴击资格与附带效果包；不按技能名字猜测整份角色或装备应被排除。
- 冰属性暴击·改的 +2,000 是该技能的固定冰魔法上限。技能参与时它对普通和暴击命中均生效；开关关闭时随相关技能包不计入。不是把它改成“仅暴击 +2,000”。对应的冰魔法上限组由 15,000 变为 13,000，其他冰魔法来源保留。
- 原始读取证据和面板不被改写。被本次选项排除的读取记录仍可查阅，并标注不计入；不得由补充加成绕回计算。
- 重新启用恢复原采用选择，已删除或手动排除项不自动恢复。首次出现的条目可沿用用户明确选择的整表来源；无法对应的读取值不自动确认。
- 真正仅暴击的增伤和固定上限分别传入暴击分支，普通分支不使用。核对表把暴击专用同名项目单独标注“仅暴击”。暴击显示对照不等于100%暴击；整次期望继续按实际采用暴击率计算。
