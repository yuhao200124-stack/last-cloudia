# 角色页技能名称与说明＝游戏数据原文（2026-09-28）

用户要求：角色页里每个技能的名字和效果必须是游戏数据库里的原文，不用最早机翻的技能表；以后新建角色也必须一样。主技能表（`index.html`／`data.js`）之后会删除，本轮不改它的名称。

## 规则

- 个性、专属技能、通用技能、超越、特技／超必杀、魔法、专武卡的名称与说明，全部由 `scripts/sync-character-game-text.mjs` 从 `dist/game-data/c/<unitDressId>.json`（局外读取器从游戏主数据导出）写入角色页。
  - 被动：`passives[id].nameS`／`textS`；特技、超必杀、魔法：`nameS`／`explainS`（导出时由 `publish.py` 用 OpenCC 转成简体）；专武卡：装备 `nameS` 与其被动的 `textS`（只替换“最高效果”一栏）。
  - 说明中的换行按空格连接；原文里的日文字形（如 攻撃、効果、麻痺、悪行症候群）照用。
- 每个技能行、个性卡、专武卡都带 `data-game-id`（被动编号／技能编号／装备编号）。脚本按编号取数据，不靠名字匹配。
- 原文没写出的数值全部自动补上，不需要逐条登记（`docs/game-text-fills.json` 已清空，只在游戏数据本身有误时用 replace／append 更正）：
  - 说明里的“{0}”由导出直接代入（`local-migration-tools/game-data/gametext.py`，支持 `1:3:*:2`、`2:7:/:100:+:10`、`2:10:/:[5]` 等全部写法），全游戏数据里不再有“?”。页面上若还出现“?”，脚本报错。
  - 专武按最高强化：导出给每件专武列出最高神装阶段的被动（`maxPassives`，同名被动中编号在其后 1～9 的最高者），专武卡“最高效果”用它。
  - “始终保持「速充」效果”这类只写状态名的句子：导出列出每个被动的常驻效果处理（`autoStates`，ProcessMst 中 `PB_オート…` 的处理及其解析值），脚本按状态名对应到同类处理，把效果和数值写在这句后面，如“始终保持「速充」效果（充能恢复速度+25%）”“常时保有高阶护盾与高阶魔法屏障的效果（受到的物理伤害-35%、受到的魔法伤害-35%）”。状态名和数据对不上时以被动实际的常驻处理为准（如个别装备原文写「提速」、数据是速充）；没有常驻处理、只有一条带条件的同类处理时用那一条（如体力低于50%时的自愈）。
  - “一定机率／有机率／低机率”：读取器几率能一一对应时写在该词后面，如“一定机率（40%）”“一定机率（特技0.25%、超必杀0.8%）”。对不上的（说明里的机率处数与数据里的几率个数无法对应）保持原文，脚本运行时列为提示，不报错。
- `tests/character-game-text.test.mjs` 对 `dist/game-data/index.json` 的 `site` 里每个角色检查：页面必须与脚本输出完全一致，每一行都有 `data-game-id`。不符合就过不了测试。

## 新建角色的做法（整页自动生成）

网站角色编号就是 Altema 的角色编号（`https://altema.jp/lastcloudia/chara/<编号>`，头像也取自 Altema）。登记表：`docs/site-characters.json`。

1. 打开该角色的 Altema 页面，读属性表：Lv1 一列（HP、MP、STR、DEF、INT、MND）和“合計”一行（Lv120＋限界突破＋潜在觉醒＋神域开眼）。容器里的命令行连不上 Altema，由 Claude 用网页读取完成；Altema 页面太长时读取可能截断（梅莉的页面就读不到属性表），需要换个问法再读或请用户提供数字。
2. 运行 `node scripts/new-character.mjs <编号> --lv1 HP,MP,STR,DEF,INT,MND --max HP,MP,STR,DEF,INT,MND --checked <日期>`。脚本会：
   - 按 Lv1 六项属性在游戏数据里自动找到 unitDressId（全库只有几个早期／测试角色 Lv1 相同，遇到时按提示用 `--unit` 指定）；找不到说明游戏数据里还没有这个角色，要先用读取器重新读取并导出；
   - 登记到 `docs/site-characters.json`，并写入 `dist/game-data/index.json` 的 site（伤害计算器据此读取招式参数）；以后重新导出时 `publish.py` 从登记表写 site；
   - 由 `scripts/character-page-builder.mjs` 按 `scripts/templates/character-page.html` 从游戏数据生成整页 `dist/character-<编号>.html`：个性、专属技能（圣物学不到的）、专属装备（同 SERIAL_NUM 的多阶装备只取 RARE 最高的一阶，最高属性和最高效果用该阶）、通用技能（圣物可学，显示 SC）与超越、魔法（圣物可学的为通用，显示 SC／MP；其余为专属；不可叠加魔法标 data-non-stacking）、特技与超必杀技；名称与说明再由同步脚本写入；
   - 在 `dist/characters.html` 加角色卡、在 `dist/app.js` 的配装角色表加一项。
   同一角色再运行一次会原地更新；早先手工整理的页面（登记表 generated=false）不会被覆盖。
3. 以后重新导出游戏数据后运行 `node scripts/sync-character-game-text.mjs`：自动生成的页面会整页重建（游戏里新加的技能也会进来），手工页面只同步名称与说明。
4. dist 改动照例加保全层、跑全部测试后提交。
5. 计算器里该角色专属技能的效果规则、“基础伤害上限／最终伤害上限”面板的上限来源，还要另外做（页面先只列出攻击方式和基础上限）。

生成页面暂不含：Altema 上的属性／异常耐性一栏；头部只写属性和物理／魔法，不写“输出／辅助”这类定位。

## 核对结果

- 最大阶段属性：Altema 属性表“合計”与阿尔克 245、艾莉丝 259、洛琪希 260 页面原有数值逐项一致，Lv1 属性与游戏数据一致；梅莉 182 的 Altema 页面读取时截断，未复核，登记表记为页面原有数值。
- 导出里的装备类型编号原先对错了（11 写成刀、12 写成斧等）。按全部装备名称核对后改为：10 剑、11 斧、12 枪、13 锤、14 弓、15 机械、16 爪、17 杖、20 铠甲、21 衣服、22 长袍、30 饰品、40 外观。只影响游戏数据文件里的类型文字，计算器没有用到。

- 游戏数据数值与计算器规则一致。梅莉两件专武的页面最高效果使用神装强化后的被动（1020482：伤害 +40%、上限 +6,000、攻击 +15%；1012782：光暗伤害 +35%、上限 +5,000、暴击率 +7%），与规则原有数值相同，现由导出的 `maxPassives` 自动取得。
- 艾莉丝「拜托你了喵☆」页面原写“实测约28/100次”，游戏数据为发生几率 40%，现自动写成“一定机率（40%）”。
- 游戏数据中“神族护罩”（16611、27954）两个不同被动同名，属游戏原数据如此。
- 自动补值覆盖面（按全游戏 3,878 个被动试算）：带“始终保持／常时保有…效果”的 259 条都能写出数值（没补的本身已写数值）；带机率词的 433 条中 368 条补上几率；21 条说明里的机率处数与数据里的几率个数对不上，保持原文并列为提示；其余的数据里本来就没有几率值，保持原文。“物理攻击的破防值…效果提升至+200”一句游戏原文就没有 %，按原文显示。
- 重新导出游戏数据：`python3 local-migration-tools/game-data/fulldata.py` 后 `python3 local-migration-tools/game-data/publish.py`（只重写 `dist/game-data/c`、`magic.json`、`relics.json`、`index.json`，不动 `engine/`、`lua/`）。
- 主技能表与游戏数据的旧对照有一条配错（麻痹研究被配成 9400 疾病研究），已在 `docs/game-relic-passives.json` 取消，游戏数据技能表重新生成；麻痹研究的游戏名为 9300 麻痺研究。
