# 基础计算器：效果拆分与条件判定

本阶段根据勾选条件判断效果，合计同类且单位相同的已生效词条，保留完整原文与来源。**这些合计不是最终伤害倍率，不能把不同维度的合计再次相加；不会将描述匹配等同于实测通过。** 伤害公式、逐段上限和技能推荐属于后续阶段。

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `dist/effect-rule-engine.mjs` | 共用条件字段、上下文规范化、效果资格判定及文字格式化；不按角色名称猜效果。 |
| `dist/roxy-rules.mjs` | 洛琪希的原文与声明式拆分示例，包含个性、专属、通用、超越和装备。 |
| `dist/effect-totals.mjs` | 只汇总 active 条目，普通属性与状态属性分开，固定值、百分比、倍率不得混加。 |
| `dist/effect-rule-learning.mjs` | 按完整描述匹配已确认模板、校验导入数据，以及识别完整且简单的直接属性描述。 |
| `dist/base-rule-calculator.mjs` | 收集页面原文、显示条件与结果、人工编辑、浏览器保存和导入导出。 |
| `dist/base-rule-calculator.css` | 计算器及编辑器样式。 |

一条来源可包含多条独立规则；一条规则的条件按“同时满足”处理，集合条件可表达同一字段的多个允许值。不同条件范围必须分开，不能把某一句的限制扩大到整条个性。命中翻倍、特攻、属性参照等保留各自的效果类型，不改写成普通增伤百分比。

## 接入新角色

1. 在角色页保留唯一的 `body[data-character-id]` 和角色名称 `.hero h2`。沿用现有角色页的计算器开启、关闭及遮罩结构。
2. 在 `head` 引入 `./base-rule-calculator.css`；给基础计算器的 `aside#bonusCalculator` 添加 `data-rule-calculator`。保留内部的 `#bonusSummary`、`.calculator-tools`，以及已有的 `#bonusCalculatorOpen`、`#bonusCalculatorClose` 按钮。
3. 在页面引入 `<script type="module" src="./base-rule-calculator.mjs"></script>`。模块仅接管带 `data-rule-calculator` 的面板，避免同时运行旧版基础效果汇总。
4. 按下列 DOM 约定保留完整原文。来源名称用于展示，规则匹配依据完整描述。

| 来源 | 页面约定 |
| --- | --- |
| 个性 | `#traits .trait`，名称在 `h4`，完整描述在 `p`。 |
| 专属／通用技能 | `#exclusive-skills`／`#common-skills` 的 `tbody tr`，名称有 `.skill-name`，最后一格为完整描述。 |
| 超越 | 技能名称同时有 `.transcend`，单独归入超越来源。 |
| 装备 | `#equipment .equipment-card`，名称在 `h4`；当前适配器取第 2 个 `dd` 为最高属性、第 3 个 `dd` 为最高效果。布局不同时应明确调整适配器，不能读取错位内容。 |

5. 先让共用模板匹配现有描述。需要预置新角色的复杂规则时，新建角色声明模块，并将其加入 `buildCatalog` 使用的种子规则集合；当前 UI 只直接导入洛琪希种子，不能只创建文件而不接入。新增规则应有唯一来源 ID，并增加与页面原文一致性的测试。
6. 角色专属的招式名称、已知元素和装备关联应单独配置。其他角色默认使用通用招式标签和待确认属性，不能沿用洛琪希的冰属性、法强／魔抗参照或专属装备映射。

装备效果默认关闭，勾选后才判定其条件。界面默认一件武器，可切换无武器／两件武器；旧字符串数字会迁移为数字。引擎仍支持显式未知条件并保留待确认。普通攻击、特技 1／2／3、魔法、超必杀分别选择。冰魔法同时满足“魔法”和“冰属性”条件，但 INT/MND 参照不等于魔法伤害类型。伤害类型未知时仅提示相关加成待确认；本界面不展示实伤估算或每击触发预测。

## 未知原文与人工纠错

匹配次序为：人工保存的完整描述模板 → 完整描述一致的预置规则 → 严格限定的简单属性解析 → 整条待确认。显式保留的当前角色本地修改可覆盖共享规则。

“完整描述一致”仅进行空白、全角加号和百分号的规范化；保留标点、句号与条件范围。名称相同但描述变化，不继承旧规则；不同名称但完整描述一致，可复用。不能凭角色名字或出现“冰”“Boss”等关键词猜分组，也不能只解析前半句而丢弃后半句条件。

人工编辑时保留对应原句；不清楚的部分设为 `pending`。`ready` 只表示描述已确认，`verification: untested` 仍表示特殊结算尚未实测。生效结果分为生效、未生效、待确认和未启用；不要把待确认显示为确定的零收益。

## 合计原地展开与修改

1. 默认“当前生效加成”，保留分类列表样式，每行显示同类加成总数，没有来源的项目和空分组自动隐藏。主页面仅保留 HP全满、命中弱点、重魔法（我方不可叠加魔法发动中）、濒死四个状态；满血与濒死互斥。攻击、元素、武器、装备和必要的魔法类别仍用于资格判断。
2. 单击某项（手机轻触、键盘回车或空格）在该行下展开来源，再次点击收起；可以同时展开多项。只取该项 active 贡献，列出来源名称、本项数值和完整技能效果，原文直接显示；“本项计入”、条件说明、停用按钮和关联停用提示默认折叠，点击“显示完整”后展开。不会切换页面或滚动到顶部。未满足单／双武器等条件的词条不混入列表。法术联结在魔法伤害来源卡内选择0–5档：用户确认4%／8%／12%／16%／20%，不再将第3、4档降为待确认。0档保留可调来源并明确未叠加，不增加总数，避免隐藏入口后无法设置。
3. 从展开的来源打开修改弹窗，保存后更新合计和来源，保留展开状态、滚动位置及操作焦点。法术联结档位调整也保留展开状态。

“更多操作”提供全技能管理、恢复停用、规则导入导出；未确认内容另列且不混入合计。停用以独立规则段为单位，界面须说明同段其他效果也会停用。

来源技能名支持双击定位角色资料中的原始行（键盘回车、触屏轻触也支持）。按来源保存的 DOM 引用精确定位，不按相似名称匹配；保持基础计算器打开，滚动角色资料到原始条目居中，复用整行高亮；计算器勾选、展开和数值保持不变。修改、层数选择等控件不会触发定位。

## 收录核对标记

基础计算器打开时，在角色资料中每个个性、专属技能、通用技能／超越和装备的名称左侧显示核对框，包括尚无已生效贡献的来源。双击计算器来源名称定位原始条目后将其设为已勾选，重复定位不会取消。原始条目也可手动勾选或取消。

关闭基础计算器时核对框隐藏，重新打开与刷新页面后恢复已保存标记。顶部“清除核对”仅清除当前角色的核对记录，不修改条件、停用项、学习规则或加成合计。记录独立保存在 `lc-effect-audit:character:<角色ID>:v1`，以类别、名称及完整描述为身份；插入条目不会错位，描述变化后需重新核对。其他标签页的核对变更会同步。

## 加成统计与事件的区别

暴击伤害是可用加成，按属性资格在“暴击与咏唱”列出，不要求勾选“这一击暴击”；这不会触发暴击回血。贯导在“伤害增加 → 魔法魔抗修正”保留来源内的“贯导触发”开关：默认不计入，勾选后显示敌方魔抗按50%计算，选择随角色配置保存。未触发时仅保留可选入口，报告中该贡献标记 `included: false`；仍须满足魔法及其他条件，停用或待确认规则不会获得入口。不改变魔法增伤百分比合计，不假定触发概率，也不视为对Boss施加魔抗降低状态。首次濒死治疗等一次性事件保留原文和编辑条件，不认定已经触发。角色按存活入场且自身开场增益存在统计；是否学习／启用技能仍可从来源管理。

## 保存与迁移

修正目前保存在当前网站、当前浏览器的 `localStorage`，不是服务器共享知识库。角色配置键为 `lc-effect-rules:character:<角色ID>:v1`，通用模板键为 `lc-effect-rules:learned:v1`。

勾选“保存为通用规则”时用于相同完整描述的后续复用；不勾选则只保留当前角色修改。通过“导出学习规则／导入学习规则”备份或迁移模板。导出判定报告保存的是当前攻击条件与判定结果，不是最终伤害，也不是全部角色配置备份。导入必须先完整校验，不能执行规则文件中的代码。

## 验证

在仓库根目录运行：

```sh
node --test tests/roxy-rules.test.mjs tests/effect-rule-learning.test.mjs tests/effect-totals.test.mjs
```

新增角色时补充对应声明测试，并至少检查：

- 页面完整原文与声明一致；无法识别的内容保持待确认。
- 冰魔法继承一般魔法条件；科学／圣剑的排除仅影响对应多段规则。
- 武器数量未知、0、1、2 件和装备勾选切换，各自影响正确规则。
- 特技 1／2／3 的选择相互独立；特殊属性参照不自动改变伤害类型。
- 编辑、刷新、导出再导入后规则保持一致；相同描述复用，描述变化不复用。

浏览器中还应确认面板可开关、编辑器可保存自动解析和待确认条目、移动端可操作，以及条件变化立即更新原因说明。游戏实测需另留数据与记录；上述测试通过只证明规则判定和交互符合声明。
