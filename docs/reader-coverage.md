# 入场报告解析覆盖（2026-09-24）

本轮逐项核对用户洛琪希 v0.35 报告的 137 个 Buff、143 条操作。`137/137` 是容器采集完整，不是所有增益已触发。6 条操作是同 Buff 的装备属性／多段魔法派生镜像，只保留证据，不重复加算。

## 解析与来源

- `reader-process-evidence.mjs` 保存三份用户报告出现的 74 种处理条件签名；65 个函数在用户提供的 `process.lua` 有参数文档。该表只限制已见布局，不表示外层条件逐位实现已全部验证。
- `reader-bonus-decoder.mjs` 从真实 raw 参数解码数值；角色来源 ID 只命名及对应，不提供数值。网站数值不作为读取器解码默认值。
- 补充单武器、指定属性魔法、装备条件魔法／物理、Boss、暴伤、特攻威力、固定上限、HP 暴击率、魔法暴击资格、装备自身强化、开场属性转换、多段魔法、魔术共鸣、指导者及法术联结。
- `1050900` 是 `KillerPower`，单列特攻威力。原生 `ProcessWork.CalcKiller` RVA `0x185DE00` 将攻方及守方修正相加，加 1、下限 0 后乘基础特攻倍率。不可再进入普通后置增伤。
- `BattleUnit.ProcBulletHit` RVA `0x176B9F0` 的魔法分支检查 MultiBullet flag120，`0x176BC54` 设置两次循环；6000 经万分率换算为单次 0.6。`buff1082500` 排除特殊魔法时取消一轮并恢复另一轮原倍率。派生记录的零槽不能覆盖父定义的6000。
- `criticalRaw` 直接是百分点；`CalcCritical` RVA `0x1840220` 直接与 0～100 随机数比较。单位面板 CRT 和 Bullet 的攻击附加 CRT 分开：读取面板11%不可再加已含常驻8%；按冰攻击参数额外5%得到16%，并不宣称该入场瞬间已应用满血10%。

## 条件与重复

- 先解码，再按选项筛选；魔法继承属性条件，普通攻击／特技为原生物理技能分类，超必杀不因选了物理参照而获得该分类的增幅。
- 共鸣保留“赋予配置”标签，仅在用户选择对应魔法进行中条件时计入候选统计。
- 指导者开场和40秒刷新是同一增益；按严格来源、效果、值及条件合并，不按同值全局去重。冰／雷配置按当前元素取一项。
- `1082699` 只在同来源、同索引的有效单武器／无武器控制配置可验证时推导条件追加。与相同作用范围的基础上限合并，例如7500+7500。实际通用计数没有采集，仍标为配置推导。
- 衣服 `1082459` 的 `(index,min,max)=(0,0,0)` 有脚本依据：`GetGeneralCount(0)=0`，`calcCoe(0,0,0)=1`。
- 连续施法按读取的区间和上限、用户选择的次数算当前值；目标受击数、未知通用计数和限时增益状态缺失时不使用最大值。
- 禁用／移除／忽略记录不能通过逐项采用绕过筛选；导入文件里的旧 `decoded` 先丢弃，再重新解码原始字段。
