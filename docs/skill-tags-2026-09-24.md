# 用户确认的条件标签规则

本轮继续原站。先按用户逐项教授的分类标记技能，不能自行扩展一套新的分类方案。全部技能标签完成后，再做截图位置的选项和技能推荐。角色自带技能所对应的选项届时默认生效，用户再从通用技能池补选；该界面流程现在不实现。

## 当前确认的细分

- 濒死：生命鼓舞等“HP越低、属性越高”的技能归入此类，性质为条件属性提高，不是Buff。标签是检索归类，不意味着仅HP≤30%才生效，更不意味着一勾选就直接算最高50%。保留动态HP依赖，数值公式仍待确认。
- 多人：魔兽同盟归入多人，具体条件是队内装备该技能的人数（含自身），2/3/4人对应5/10/15%。不能用“多人联机”布尔值替代这个人数。
- 空手：分为空武器、空防具、都空。光头猴属于“都空”，两条件同时满足。裸身系列仅要求空防具，徒手空拳等仅要求空武器，不能相互替代；饰品不纳入武器/防具的空栏判断。
- 单手：按实际只装备一把武器，以及剑/斧/枪/弓/锤/爪/机械/法杖等具体类型记录。技能名叫“两手剑”也按原效果的“一把剑”归类。
- 双手（双持）：两把武器；武器类型限制与相同关系独立保存。相同类型如剑+剑；相同属性如冰+冰。两把同类武器不等于必须是同一个道具ID，同属性也不等于同类型。没有写同类/同属性要求时，不能额外添加要求。

目前来源中“同类二刀增幅”要求同类型，“和谐节拍”要求同属性；不因用户口头统称相同就合并这两种机械条件。某种武器双持使用同一个weaponTypes字段配合weaponCount=[2]表示，未找到已确认来源时不凭空造技能。

## 数据与边界

`skill-tag-registry.json` 是人工可核对原稿，保存原ID、原完整描述、原URL、条件路径、精确条件和适用原文片段。`scripts/build-skill-tags.mjs` 校验完整原文后生成 `dist/skill-tag-catalog.mjs`，并在原分类表的同技能副本上复用同一份标签。

本轮76个唯一技能，81个条件片段标签；全部标记为 partial，表示只完成本轮条件维度，**不是这76个技能的所有效果都已打完标签或接入计算**。现有库去重935、主表933、基础属性181均保持不变。

复合技能的条件按片段保存。例如荒神御魂的无条件HP-15%不受“空武器或单手”条件限制；这个条件仅属于后半段追加上限。标签本身不直接改变伤害计算，不能拿装备标签替代同一片段里尚未分类的特攻、弱点、背击等条件。

技能页面显示、搜索标签；配装快照携带结构化标签供后续推荐使用。自定义描述会停用原标签，避免把已改成另一种效果的技能按旧条件推荐。改名仍按稳定ID关联。

基础属性说明同步细化：光头猴明确“都空”，四个裸身属性技能明确“空防具”，剑雷明确“一把剑”；生命鼓舞/生命堡垒显示“最高50%，非固定50%”，魔兽同盟列出人数阶梯。动态数值和人数未由用户提供时继续待确认，不套最大值。

## 选项区暂缓

用户最新要求优先于上一轮的选项扩展。上一轮尚未发布的受伤/复活/使用必杀/周日/必杀槽满入口先标为deferred，保留已实现计算规则与内部字段，但不向截图中的可见选项区增加选项。保持现有双刀、特攻、break、满血、濒死、暴击、开场Buff、觉醒Buff、魔导觉醒Buff。

原站源码服务此前持续返回503。发布成功与否必须单独根据实际部署结果报告，不能把本地标签完成写成线上已更新。

## 补充：按效果片段逐类贴标签

用户明确：一个技能有几种效果，就可以关联几种标签。例如“类型追加龙；攻击力+10%；物理减伤15%”关联类型追加、攻击力、物理伤害减少。仅处理攻击力时，整体仍为判断部分。

每增加一种标签，必须从全库去重技能查找，包含主表和分类独有项；不能仅从基础属性页或已标记的某一类技能中找。贴标签按稳定ID关联原技能，不复制出新的独立技能身份，不重复计SC或加成。所有标签完成后才展开新的战斗条件选项和推荐流程。
